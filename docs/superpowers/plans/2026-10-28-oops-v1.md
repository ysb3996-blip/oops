# oops v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `oops`, a Ruby CLI that copies the last shell command and its output to the clipboard in a paste-ready fenced block, by recording the shell through a pty relay.

**Architecture:** A shell snippet (`oops init zsh|bash`) re-execs the interactive shell under `oops record`, a Ruby pty relay that forwards bytes both ways, forwards SIGWINCH, and strips APC markers emitted by shell hooks. The relay parses the output stream into per-command records (capped at 1MB, full-screen spans dropped) and appends them as JSON Lines to a per-tab session log. The `oops` command reads the log backward, formats (strip ANSI, mask secrets, apply replace table, head/tail, fence) and copies via a detected clipboard backend.

**Tech Stack:** Ruby 3.2+, stdlib only (`pty`, `io/console`, `optparse`, `json`, `yaml`, `base64`), Minitest, Rake, GitHub Actions (ubuntu + macos).

**Spec:** `docs/superpowers/specs/2026-10-28-oops-v1-design.md`

## Global Constraints

- Ruby >= 3.2. No runtime gem dependencies. No native extensions. (spec §3)
- Gem name `oops-cli`, executable `oops`, GitHub repo `oops`. (spec §3)
- All code, CLI messages, README in English. (spec §3)
- Must work on macOS and Linux (WSL counts as Linux), zsh and bash 3.2+. Do not use bash 4+ features in the bash snippet. (spec §3)
- `oops` must answer within 200 ms including Ruby startup; never read a session log from the beginning. (spec §7.3)
- The relay must never let an exception escape its forwarding loop; losing the log is acceptable, losing the shell is not. (spec §7.1, §8)
- Commit messages: plain conventional commits. Do not add any AI attribution lines (`Co-Authored-By`, `Generated with`) to commits.
- Never run `oops record` against the implementer's own real terminal session during tests; integration tests spawn their own pty.

## Review Focus

1. **Marker split across read chunks** (spec §8): a start/end marker arriving in two `feed` calls must still be parsed and not leak to the terminal. Pinned in Task 8.
2. **A command emitting more than 1MB** (spec §7.4): the record keeps the last 1MB, `dropped_bytes` is correct, and the `exit` code is still captured from the end marker. Pinned in Task 8.
3. **Output containing a triple backtick** (spec §5.1): the fence becomes four backticks. Pinned in Task 5.
4. **Window resize while recording** (spec §7.1, §8): the inner shell sees the new size. Pinned in Task 9 (integration).
5. **Log directory not writable** (spec §8): the relay still forwards bytes and the shell keeps working. Pinned in Task 9.

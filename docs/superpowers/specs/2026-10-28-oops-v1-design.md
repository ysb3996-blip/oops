# oops v1 設計書

作成: 2026-10-28。改訂 1(同日): 作り手レビューを受けて録画機を `script` から Ruby 自前の pty リレーに変更、コマンド行にも伏せ字を適用、録画中判定を tty の同一性に変更、再 exec するシェルの決め方を明記。
対象: oops v1(最初の公開リリース)。
この文書は、実装者(人でもClaudeでも)が作者に聞き返さずに実装計画を立てられることを目標に書く。

## 1. 何を作るか(intent)

`oops` は、シェルで直前に実行したコマンドとその出力を、Claude・Slack・GitHub などに貼れる形でクリップボードにコピーする CLI。Ruby で書き、RubyGems と Homebrew(自分の tap)で配布する。

**目的はひとつ**: 「端末で出力をドラッグして選び、コピーして、貼り先で ``` を付ける」手間を、「`oops` と打って貼り先で ⌘V」の2手にすること。設計の取捨選択はすべてこの目的で判断する。手間が減らないものは入れない。速度は体感で「一瞬」なら十分。

使う場面の例:

- テストが落ちた。別の Claude に「これ直して」と貼りたい → `oops err`
- デプロイのログを Slack で共有したい → `oops`
- 再現手順と結果を issue に貼りたい → `oops 3 --github`

## 2. ゴール / 非ゴール / アンチゴール

### ゴール

- `oops` だけで貼れる形になる。フラグなしで実用になること
- 貼り先で手直しが要らない(色コードなし、``` で囲まれている、個人情報が伏せられている)
- 「選ぶ」手間が無い。`oops err`(直前の失敗)や `oops 3`(直近の流れ)で、ドラッグせずに狙ったものが取れる
- どの端末アプリでも同じに動く(Ghostty・iTerm2・Terminal.app・VS Code内蔵・GNOME Terminal 等)
- macOS と Linux(WSL含む)、zsh と bash で動く
- 利用者のシェルを壊さない。oops の何かが失敗しても、普通のシェルとして起動する

### 非ゴール(v1ではやらない)

- fish 対応(次のバージョン)
- Windows ネイティブ(PowerShell / cmd)
- 直前のコマンドの再実行による出力取得(副作用の二重実行と出力の非再現性のため、方式として採らない)
- Slack への直接投稿、gist へのアップロード(貼り先が毎回違うので決め打ちしない)
- 画面出力(`--print` の類)。oops はクリップボードに入れるためのツール
- 貼り先ごとのプリセット(`--slack` `--claude`)。既定の形がどこでもコードブロックになるので不要
- 色の保持。貼り先で色は意味を持たない
- 対話式の選択 UI(`oops pick`)
- 端末のスクロールバックを使う方式(tmux / kitty / WezTerm)。端末依存のため v1 では使わないが、録画機を差し替えられる構造にはしておく
- OS 標準の `script` コマンドの利用(macOS の `script` はウィンドウのサイズ変更を中のシェルに伝えないため、使わない)

### アンチゴール(技術的に動いても失敗とみなす)

- 利用者がシェルを起動できなくなる、入力が化ける、ペーストした文字が欠ける、ウィンドウのサイズ変更が中のアプリに伝わらない
- 既定でトークンやメールアドレスが Slack に貼られる(伏せ字は既定で ON。打ったコマンドの行も対象)
- `oops` と打ってから1秒以上待たされる
- ログがディスクを食い潰す(長時間開きっぱなしのタブでも上限が効くこと)
- 録画機のプロセスが落ちてシェルが巻き添えになる

## 3. 制約

- Ruby 3.2 以上。実行時依存 gem は無し(stdlib のみ: `pty` `io/console` `optparse` `json` `yaml` `base64` など)。ネイティブ拡張なし。Homebrew での配布を簡単にするため
- OS: macOS、Linux。WSL は Linux 扱い
- シェル: zsh、bash(macOS 同梱の 3.2 でも動くこと。bash 4 以降の機能に依存しない)
- 外部コマンドへの依存はクリップボードツールのみ。実行時に検出し、無ければ代替か明確なエラーにする
- 録画中はタブごとに Ruby のプロセスが1つ常駐する(実測 16.6MB RSS)。これは受け入れる
- 公開 OSS。コード・コマンドのメッセージ・README は英語。この設計書は日本語
- 名前: コマンドとリポジトリは `oops`、gem 名は `oops-cli`(RubyGems の `oops` は取得済み)。実行ファイル名は `oops`

## 4. 使い方(インターフェース)

### セットアップ

```sh
gem install oops-cli      # or: brew install takeuchi/tap/oops (後日)
```

そして **rc ファイルの先頭に**(他の設定より前に)1行足す。

```sh
# ~/.zshrc の先頭
eval "$(oops init zsh)"
# bash は ~/.bashrc(macOS で .bash_profile に書いている人はそこ)の先頭
eval "$(oops init bash)"
```

先頭に置く理由: スニペットはシェルを録画機付きで起動し直す(`exec`)。先頭なら、その前にある処理(nvm、starship 等)が外側と内側で2回走らない。末尾に置いても動くが、起動が遅くなる。README にこの理由ごと書く。

新しいタブを開くと録画が始まる。既存のタブは `exec zsh` で再読み込み。

### コマンド

| コマンド | 動作 |
|---|---|
| `oops` | 直前のコマンド+出力をクリップボードへ |
| `oops 3` | 直前3コマンド分(古い順)を1つのコードブロックで |
| `oops err` | 直前の「終了コードが 0 以外」だったコマンドを拾う。間に成功したコマンドが挟まっていても遡る |
| `oops init zsh` / `oops init bash` | シェルに組み込むスニペットを標準出力に出す(eval 用) |
| `oops doctor` | 録画中か、フック・クリップボード・設定・ログ容量の診断 |
| `oops pause` / `oops resume` | 録画の一時停止/再開(停止中は `doctor` に表示) |
| `oops record -- <shell> [args]` | 内部用。録画機(pty リレー)としてシェルを起動する。スニペットが呼ぶ |
| `oops --version` / `oops --help` | 省略 |

### オプション(`oops` / `oops N` / `oops err` に付く)

| オプション | 動作 |
|---|---|
| `--github` | GitHub の issue/PR コメント向けの形(5.4 参照) |
| `--tail N` | 出力の末尾 N 行だけ残す。省いた分は `... 2,950 lines omitted ...` の1行に置き換える |
| `--head N` | 出力の先頭 N 行だけ残す。`--tail` と併用可(先頭と末尾を残し、間を省く) |
| `--show-secrets` | 伏せ字と置き換え表を適用しない(生のまま) |

`oops` 自身の実行(`oops`, `oops err` 等)は対象のコマンドから除外する。直前に `oops` を打っていても、その前の本当のコマンドが取れる。

### 終了コードとメッセージ

- 0: コピーした。標準出力に1行: `copied: $ bundle exec rspec (42 lines, 2 secrets masked)`(伏せ字 0 件なら `(42 lines)`)。この報告行のコマンド部分にも伏せ字・置き換えを適用する
- 1: コピーできない。例:
  - `oops: not recording in this shell. Add  eval "$(oops init zsh)"  to the top of ~/.zshrc and open a new tab.`
  - `oops: no command found yet.`
  - `oops: no failed command found.`
  - `oops: recording is paused. Run  oops resume  first.`
  - `oops: no clipboard tool found (tried pbcopy, wl-copy, xclip, xsel, clip.exe, OSC 52).`
- 2: 使い方の誤り

## 5. 出力の形

### 5.1 既定

```
$ bundle exec rspec
....F

Failures:
  1) User#name returns full name
     expected "Taro Yamada", got "Taro"
(exit 1)
```

上を ``` で囲んだものがクリップボードに入る(囲みの ``` も含める)。

- 1行目: `$ ` + 打ったコマンド(入力したまま。エイリアス展開しない)。複数行コマンドは2行目以降を `  `(空白2つ)で字下げ
- 以降: 出力(標準出力と標準エラーは端末に出た順で混ざったまま)
- 終了コードが 0 以外のときだけ最後に `(exit N)`。0 なら付けない
- 作業ディレクトリ・時刻・ホスト名は入れない
- 出力の末尾の空行は落とす。囲みの中は最後に改行1つ
- 出力に ``` が含まれるときは、囲みを ```` (4つ)にして壊れないようにする
- `oops 3` は1つの囲みの中に、古い順に `$ cmd1` 出力 `$ cmd2` 出力 … と並べる。コマンドの間は空行1つ

### 5.2 整形の順序

整形は「コマンド行(`$ ` の中身)」と「出力」の両方に同じ順序で適用する。コマンド行には `export AWS_SECRET_ACCESS_KEY=...`、`curl -H 'Authorization: Bearer ...'`、`git clone https://user:pass@...` のように秘密が出るため。

1. 端末制御の除去(ANSI エスケープ: CSI・OSC・APC、BEL、`\r` は「行内で最後の `\r` 以降だけ残す」ことで進捗バーを最終状態にする、バックスペースは直前1文字を消す)。コマンド行は印から復元した文字列なので通常は不要だが、同じ関数を通す
2. 不正な UTF-8 バイトは U+FFFD に置換(`String#scrub`)
3. ホームディレクトリを `~` に(`$HOME` で始まるパスの先頭置換)
4. 伏せ字(5.3)
5. 置き換え表(6.)
6. `--head` / `--tail` の切り詰め(出力のみ。コマンド行は切らない)
7. 囲みと `$ ` 行、`(exit N)` の付加

3〜5 は `--show-secrets` で飛ばす。全画面アプリ区間の置き換え(`[full-screen app output omitted]`)は録画機側で済んでいる(7.4)。

### 5.3 伏せ字(secrets)

既定で ON。該当部分を `[secret]` に置き換え、件数を報告行に出す。組み込みのパターン(最低限):

- AWS アクセスキー(`AKIA` + 16 文字)、`aws_secret_access_key` 等の値
- GitHub トークン(`ghp_` `gho_` `ghu_` `ghs_` `ghr_` `github_pat_` で始まる)
- Slack トークン(`xox[abpras]-`)
- JWT(`eyJ` で始まる3パートの文字列)
- `Authorization: Bearer <...>` / `Basic <...>` の値
- `-----BEGIN ... PRIVATE KEY-----` から `END` までのブロック
- `key` `token` `secret` `password` `passwd` `pwd` を含む名前の `=` または `:` の右辺(大文字小文字区別なし)
- メールアドレス
- URL の userinfo(`https://user:pass@host` の `user:pass`)
- IPv4 アドレス(ただし `127.0.0.1` `0.0.0.0` `localhost` と `10.` `192.168.` `172.16〜31.` のプライベート帯は伏せない)

設定ファイルの `secrets:` で正規表現を追加できる。組み込みを無効にする手段は v1 では `--show-secrets` のみ。

### 5.4 `--github`

GitHub のコメント欄向け。`console` 指定のコードブロックにする(GitHub は `$ ` で始まる行をコマンドとして色分けする)。

出力が 30 行以下:

````
```console
$ bundle exec rspec
....F
(exit 1)
```
````

出力が 30 行を超える: 折りたたみで包む。見出しに開かずに分かる情報を出す(見出しのコマンドにも伏せ字・置き換えを適用)。

````
<details>
<summary><code>$ bundle exec rspec</code> — exit 1, 312 lines</summary>

```console
$ bundle exec rspec
...
(exit 1)
```

</details>
````

`oops 3 --github` はコマンドごとに別の折りたたみ/ブロックにする。閾値 30 行は実装者が変えてよい。

### 5.5 `--tail` / `--head`

- `--tail 50`: 末尾 50 行を残し、先頭に `... 2,950 lines omitted ...`
- `--head 20`: 先頭 20 行を残し、末尾に `... N lines omitted ...`
- 両方: 先頭 20 行 + `... N lines omitted ...` + 末尾 50 行
- `oops 3` ではコマンドごとに効かせる
- 省略行の数字はカンマ区切り。行数は整形後(伏せ字・置き換え後)の行で数える

## 6. 設定ファイル

場所: `${XDG_CONFIG_HOME:-~/.config}/oops/config.yml`。無くても動く。

```yaml
replace:            # コピー時に文字列を置き換える(読みやすさを保ちつつ本名を出さない)
  takeuchi: dev
  MacBook-Pro: laptop
  leverages: company
secrets:            # 伏せ字にする正規表現を追加
  - "sk_live_[A-Za-z0-9]+"
clipboard: auto     # auto | pbcopy | wl-copy | xclip | xsel | clip.exe | osc52 | 任意のコマンド文字列(標準入力で受け取る)
```

- `replace` は単純な文字列置換。キーが長いものから順に適用。大文字小文字は区別する
- 置き換え・伏せ字はコピーする瞬間に適用し、録画ログは元のまま残す(設定変更が過去の分にも効く)
- `clipboard` に上記の名前以外の文字列を書いたら、それをシェルコマンドとして起動し標準入力に渡す(テストや特殊環境用)
- 未知のキーは警告を標準エラーに出して無視。YAML が壊れていれば警告して設定なしで続行(コピーを止めない)

## 7. 仕組み(How)

### 7.1 全体像

```
端末アプリ ── pty ── oops record(録画機 = Ruby の pty リレー) ── pty ── zsh/bash(フック入り)
                              │
                              └─ 書く ─> セッションログ(JSON Lines)  <─ 読む ─ oops(CLI)
```

- `oops init zsh` のスニペットが `.zshrc` から eval される
- スニペットは「対話シェルで、stdin/stdout が端末で、まだこの端末が録画されていない(7.2)」ときだけ、`exec oops record -- <今動いているシェル>` でシェルを録画機付きで起動し直す。条件を満たさなければ、録画中ならフックだけ入れ、非対話なら何もしない
- `oops record` は Ruby の `pty` + `io/console` で書く pty リレー。やることは:
  1. 自分の stdin(端末)の termios を保存し、raw モードにする。現在のウィンドウサイズを取る
  2. 新しい pty を作り、その上でシェルを起動する(`PTY.spawn`)。子のウィンドウサイズを端末と同じにする
  3. 端末 → 子 pty へ入力をそのまま中継、子 pty → 端末へ出力をそのまま中継(印は除いて)。同時にセッションログを書く(7.3)
  4. SIGWINCH を受けたら端末のサイズを読み直して子 pty に設定する(これが `script` を捨てた理由)
  5. 子が終了したら残りの出力を流し切り、termios を復元し、子の終了コード(シグナル終了なら 128+番号)で終わる
- 環境変数を子に渡す: `OOPS_SESSION=<ログのパス>`、`OOPS_TTY=<子 pty のデバイスパス>`
- 「シェルを壊さない」ための規則:
  - pty の作成やシェルの起動に失敗したら、警告1行を標準エラーに出し、`OOPS_DISABLE=1` を付けて同じシェルを `exec` する(スニペットは `OOPS_DISABLE` があれば何もしない。無限ループ防止)
  - 中継ループの中で起きる例外(ログ書き込み失敗、ディスク満杯、解析のバグ)はすべて捕捉し、ログを諦めても中継は続ける。`doctor` が「録画中だがログに書けていない」と分かるように状態ファイルに残す
  - 中継は入力を1バイトも落とさない。出力側の書き込みがブロックしても入力は失わない(実装者の選択: `IO.select` の単一ループか、入力/出力でスレッドを分ける)

### 7.2 「録画中か」の判定と再 exec するシェル

- 判定は環境変数の有無ではなく **端末(tty)の同一性**で行う。録画中のシェルから起動した tmux・`code .` の VS Code 内蔵端末・GUI 端末は環境変数を引き継ぐので、`$OOPS_SESSION` の有無だけだと「録画中」と誤判定し、印が外側のログに届かない
- zsh: `[[ -o interactive && -t 0 && -t 1 && -z "$OOPS_DISABLE" ]]` かつ `"$OOPS_TTY" != "$TTY"` なら録画開始。等しければフックだけ入れる
- bash: `[[ $- == *i* ]]` と `-t 0 -t 1`、tty は `$(tty)` で取る(シェル起動時に1回だけ)
- 再 exec するシェルは `$SHELL` ではなく **今動いているシェル**: zsh は `$ZSH_ARGZERO`(先頭の `-` を除く。無ければ `zsh`)、bash は `$BASH`
- ログイン状態: zsh は非ログインの対話シェルとして再 exec する(環境は継承されるので `.zprofile` を2回走らせない)。bash はログインシェルなら `-l` 付きで再 exec する(macOS の慣習で `.bash_profile` に設定を書く人が多く、非ログインだとスニペットが読まれないため)
- tmux の中: tmux が開くシェルは別の tty なので、それぞれ録画される。外側(tmux を起動したシェル)のログには tmux の全画面区間が溜まるが、7.4 で捨てる
- 二重録画の最後の砦: `oops record` は `OOPS_TTY` が自分の stdin の tty と同じなら何もせず `exec` でシェルに落ちる

### 7.3 セッションログ

- 置き場所: `${XDG_STATE_HOME:-~/.local/state}/oops/sessions/<開始時刻>-<pid>.jsonl`。ディレクトリは 700、ファイルは 600
- 1タブ(録画機1つ)につき1ファイル。`oops` は `$OOPS_SESSION` でどのファイルを読むか知る
- 形式は JSON Lines。1行 = 完了した1コマンド:

```json
{"seq":12,"cmd":"bundle exec rspec","cwd":"/Users/takeuchi/dev/app","started_at":1761620000,"ended_at":1761620012,"exit":1,"output":"<base64 の生バイト列>","dropped_bytes":0,"fullscreen":false}
```

- `output` はエスケープ文字を含む生のバイト列(base64)。整形は読む側(5.2)がやる。「ログは元のまま、設定は後から効く」原則のため
- `dropped_bytes`: 1MB 上限(7.4)で捨てた先頭のバイト数。`fullscreen`: 全画面区間を省いたか
- 録画機は終了印を受けた時点で1行を書き、flush する(fsync は不要)
- シェルが終了したときに未完了のコマンドがあれば `exit: null` で書く
- `oops` は末尾から後方に行単位で読み、必要な件数が揃ったら止める(先頭から全部読まない)。`oops` の応答は 200ms 以内を目標(Ruby の起動 60〜80ms を含む)
- 録画機は、印を自分で解釈するので、印のバイト列は端末に流さない(端末の種類に関係なく確実に見えない)

### 7.4 印(マーカー)と上限

シェルのフックが、コマンドの前後に印を書く。印は子 pty を通って録画機に届く。

- zsh: `preexec`(引数 `$1` に入力したコマンド全文)と `precmd`
- bash: `PROMPT_COMMAND` と `DEBUG` trap。bash-preexec(MIT)の手法をスニペットに同梱(vendoring)する。コマンド全文は `history 1` から取る
- `precmd` / `PROMPT_COMMAND` では最初に `$?` を退避すること
- 印の形式は実装者が決めてよいが、要件:
  - 録画機が確実に見つけられ、チャンク境界で割れても復元できる(推奨: APC `ESC _ oops;<種別>;<項目>... ESC \`。録画機は前回の読み残しを持ち越して解析する)
  - 万一録画機を通らず端末に届いても表示されない(APC は主要端末が無視する)
  - 開始印: 連番、開始時刻(epoch 秒)、作業ディレクトリ、コマンド全文(base64)
  - 終了印: 連番、終了コード
  - pause 印 / resume 印(7.5)

上限(書きながら効かせる):

- 1コマンドあたり 1MB。実行中の出力はメモリ上のバッファに貯め、1MB を超えたら**先頭を捨てて末尾を残す**(エラーは末尾に出る)。捨てた量を `dropped_bytes` に記録
- 全画面アプリ区間: `\e[?1049h` `\e[?47h` `\e[?1047h` を見たら、対応する `l` までの出力をバッファに入れない。代わりに `[full-screen app output omitted]\n` を入れ、`fullscreen: true` にする。端末への中継はそのまま続ける
- セッションファイル群の合計 50MB: 録画機の起動時に、稼働中でない古いファイルから削除。稼働中かはファイル名の pid が生きているかで判定(`Process.kill(0, pid)`)

### 7.5 pause / resume

- `oops pause`: pause 印を自分の標準出力に書く(子 pty を通って録画機に届く)。録画機は resume 印まで出力を一切バッファに入れず、ログにも書かない。合わせて `<ログ>.paused` という空ファイルを作る(`doctor` と `oops` が状態を知るため)
- `oops resume`: resume 印を書き、`.paused` を消す
- pause 中の出力はディスクに一切残らない(`script` 時代の制約は無くなった)
- 停止中に `oops` を打つと `oops: recording is paused. Run  oops resume  first.`(終了コード 1)
- 録画機が無い(録画されていない)シェルで `pause` を打つと `not recording` のエラー

### 7.6 クリップボード

`clipboard: auto` のときの検出順:

1. macOS: `pbcopy`
2. WSL(`/proc/version` に `microsoft`): `clip.exe`(UTF-16LE に変換して渡す。`clip.exe` の仕様)
3. `$WAYLAND_DISPLAY` あり: `wl-copy`
4. `$DISPLAY` あり: `xclip -selection clipboard` → `xsel --clipboard --input`
5. どれも無い、または SSH セッション(`$SSH_TTY` あり): OSC 52(`ESC ] 52 ; c ; <base64> BEL` を `/dev/tty` に書く)。Ghostty・kitty・iTerm2・WezTerm・Windows Terminal・Alacritty が対応。端末によって1回に送れる量に上限がある(例: 100KB 弱)ので、超えたら警告して先頭を切る

OSC 52 のバイト列は子 pty を通って録画機に届くが、印ではないので端末にそのまま中継される。`oops` 自身のコマンドは除外されるのでログの邪魔にはならない。

`doctor` はどの経路が選ばれるかを表示する。

### 7.7 `oops err` の探索

末尾から遡り、「`oops` 自身でなく、終了コードが 0 以外」の最初のコマンドを返す。Ctrl-C で止めたコマンド(130)も対象。`exit: null`(未完了)は飛ばす。見つからなければ終了コード 1。

### 7.8 `oops doctor` の確認項目

- この端末は録画中か(`OOPS_TTY` と現在の tty が一致、録画機の pid が生きている、ログファイルがある)
- 録画機はログに書けているか(7.1 の状態ファイル)
- 一時停止中か
- シェルとバージョン、スニペットが入っているか(フック関数の存在)
- 選ばれるクリップボード経路と、その道具の有無
- 設定ファイルの場所と、読めたか
- セッションディレクトリの合計サイズとファイル数
- OS と Ruby のバージョン

## 8. エッジケース(実装者が迷わないように)

| 状況 | 振る舞い |
|---|---|
| 端末でない起動(Claude Code の Bash ツール、cron、IDE のタスク、`zsh -c`) | スニペットは何もしない。録画しない |
| 録画中のシェルで `exec zsh` / `zsh` と打つ | 同じ tty なのでフックだけ入れ、二重録画しない |
| 録画中のシェルから `tmux` / `code .` / GUI 端末を起動 | 別の tty なので、その中のシェルは新しく録画される(7.2) |
| `sudo -s` / `su` で環境変数が消える | 同じ tty だが `OOPS_TTY` が無い → スニペットは録画開始を試みる → 入れ子録画になる。v1 では許容(ログが2重になるだけ)。実装者が親プロセス判定で防いでもよい |
| ウィンドウのサイズ変更、ペイン分割 | 録画機が SIGWINCH を子 pty に伝える。vim・less・Claude Code が追従すること(結合テストで確認) |
| SSH 先 | 先に oops を入れてあれば先で録画。クリップボードは OSC 52 で手元に届く |
| バックグラウンドジョブ(`cmd &`)の出力 | 次以降のコマンドの出力に混ざる。許容 |
| 対話コマンド(`python` REPL、`ssh` のセッション) | 出力として記録される。全画面でなければそのまま |
| 端末への問い合わせ(`\e[6n` カーソル位置など)と応答 | 録画機は両方向をそのまま中継するので壊れない |
| `clear` | 画面消去の制御文字は整形時に除去されるだけ |
| 進捗バー(`\r` で上書き) | 整形時に行ごとに最後の状態だけ残る |
| 1行が巨大(5MB の JSON) | 上限はバイト数で効く。行数ではない |
| 出力に ``` を含む | 囲みを ```` にする |
| 出力が無いコマンド(`cd`) | `$ cd foo` だけの囲み。終了コード 0 なら `(exit 0)` は付けない |
| 直前が `oops` 自身 | 飛ばして、その前の本当のコマンドを取る |
| 最後のコマンドがまだ実行中 | 同じタブではシェルが戻るまで `oops` を打てない。別タブは別セッション |
| シェルを閉じて開き直した | 新しいセッション。前のタブの分は v1 では取れない(`oops: no command found yet.`) |
| 録画機が落ちた(バグ・kill) | シェルも終わる(pty の親が消えるため)。アンチゴールなので、中継ループは例外を全部捕捉し、ログ機能を切ってでも中継を続ける |
| ディスク満杯・ログディレクトリに書けない | 録画機はログを諦めて中継だけ続ける。`doctor` で分かる |
| UTF-8 がチャンク境界で割れる | バイトで扱い、整形時に `scrub` |
| 印がチャンク境界で割れる | 録画機が読み残しを持ち越して解析する |
| 設定 YAML が壊れている | 警告して設定なしで続行 |
| クリップボードツールが無い | OSC 52 にフォールバック。それも使えない端末なら終了コード 1 とメッセージ |
| 複数のプロンプト装飾(starship、p10k) | 印の外(終了印〜開始印の間)なので記録されない |

## 9. テストと検証

- 単体テスト: 整形(制御文字除去、`\r`、伏せ字の各パターン、置き換え表、head/tail、囲みの 4 つ化、コマンド行への適用)、ログの後方読み、`err` の探索、録画機のストリーム解析(印の抽出、チャンク境界で割れた印、全画面区間、1MB 上限)。固定のバイト列をフィクスチャにする
- 結合テスト: Ruby の `PTY.spawn` で `oops record -- bash --norc --noprofile` を起動し、`eval "$(oops init bash)"` を流し込み、コマンドを実行して `oops` の出力(`clipboard:` にテスト用コマンドを指定して受け取る)を検証する。zsh も同様(`zsh -f`)。ウィンドウサイズ変更が子に伝わることも検証する(`stty size` を変更前後で比較)。macOS と Ubuntu の両方で通す
- CI: GitHub Actions、`ubuntu-latest` と `macos-latest` のマトリクス、Ruby 3.2 / 3.3
- 性能の確認: 20MB 一気出しで素の pty と比べて 2 倍以内(先の実測: 素 1.2 秒、Ruby リレー 1.2〜1.6 秒)、小さいコマンドで差が無いこと
- 手動確認の項目(README の開発者向け節に): Ghostty / Terminal.app / VS Code 内蔵端末で印が見えないこと、vim・less・Claude Code をウィンドウサイズ変更しながら使えること、`exec zsh` で二重録画しないこと、`code .` で開いた VS Code 端末が録画されること
- テストフレームワークは実装者の選択(Minitest なら追加依存なし。RSpec でもよい)
